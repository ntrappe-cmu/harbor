# Harbor synthetic usability review — 5 October 2026

Method: scenario walkthrough of the current SwiftUI implementation, including first launch, missing credentials, offline access, preview-only runs, assistant switching, reruns, cancellation, failed stops, edited limits after stopping, missing cost reports, and budget exhaustion. This is a heuristic/synthetic evaluation, not a study with recruited users. Severity is a prediction, not measured frequency. Read-only watcher provided an independent source review.

The compact Overview usage indicator and Settings controls are implemented. The following broader fixes are proposals awaiting review.

| ID | Priority | Scenario and predicted confusion | Solution A | Solution B | Recommendation |
|---|---|---|---|---|---|
| 1 | High | Header says Ready while Run is disabled by credentials, offline access, another active workspace, or setup. Green status appears to promise task readiness. | Show a short reason directly below disabled Run, with an action when available. | Replace Ready with a checklist combining runtime, credentials, draft, and access. | A: minimal, explains the next action at the relevant control. |
| 2 | High | Cancel Task also stops the browser preview and tools. A person expects to cancel only the assistant. | Use Stop Workspace consistently and state that files and the draft are kept. | Keep Cancel Task but add separate Stop Task and Stop Workspace behavior. | A for MVP; B when task-only stopping is reliably implemented. |
| 3 | High | Remaining budget unavailable can seem broken; Codex token reports do not necessarily include dollar cost. | Inline reason: Cost not reported, with known token counts in Details. | Offer optional provider reporting integration or an explicitly estimated cost using model-specific pricing. | A now. B needs additional permissions/data and must not imply account balance. |
| 4 | High | Monthly budget looks like an enforced cap, but tasks continue charging after it is reached. | Rename to Monthly spending warning; keep compact Harbor budget on Overview with a warning-only explanation. | Add an enforced cap that blocks new starts and best-effort stops active work. | A now. B cannot promise exact spend enforcement with delayed cost reports. |
| 5 | High | Run Revised Task looks like a follow-up in the same conversation; the implementation creates a new invocation with current files. | Label Start New Task and explicitly say current files are kept but conversation starts fresh. | Implement real provider session continuation with New Task vs Follow-up controls. | A now; B is a separate feature. |
| 6 | High | Failed stop leaves runID and global previewAvailable; Open Preview can remain enabled even when preview health is unknown. | Enable only for the matching workspace in running state; show Preview status unknown after a failed stop. | Probe preview health and show Reachable/Unavailable/Checking. | A now; B can improve confidence later. |
| 7 | Medium | After stopping, changing CPU limits relabels the old CPU fraction with the new number of cores. | Save the effective core allocation with each resource reading. | Clear the old CPU reading when limits change. | A: preserves accurate historical evidence. |
| 8 | Medium | Old errors remain prominent after a successful retry, suggesting the new task also failed. | Separate Current run and Previous runs with dates and a collapsed prior-issues group. | Add explicit resolved/unresolved flags and a dismissal workflow. | A: useful chronology with less bookkeeping. |
| 9 | Medium | AI budget bar shows remaining capacity; CPU, memory, and run-time bars show consumed capacity. Same visual shape has opposite direction. | Keep explicit labels: Budget remaining, CPU used, Memory used, Time used. | Make every bar show amount used, with remaining text beside it. | A: preserves the selected budget design; label direction visibly. |
| 10 | Medium | File-type split bar and storage-warning bar can look like disk-capacity indicators. Starter files keep a grey bar after generated files exist. | Label the split bar File types by size and show actual contents once files change; label Warning threshold separately. | Replace the split bar with a file-type list and show warnings only when reached. | A: retains useful visual overview without implying quota or empty storage. |
| 11 | Medium | A task without final cost makes monthly remaining unknown for the rest of that month; known spend may already exceed the warning. | Show At least $X reported; issue a warning if that known minimum crosses the threshold, without showing a remaining bar. | Let users enter/reconcile missing task costs with clear manual attribution. | A now; B optional later. Never silently delete incomplete tasks to manufacture a balance. |

Recommended first batch: 1, 2, 3, 5, 6. Actual native interaction and accessibility testing remain necessary to confirm these hypotheses.
